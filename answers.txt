=== Question 4.2 (4 marks) ===
#Why could the tests reach the database driver but the packaged jar could not?
#(The fix itself goes in pom.xml.)
#Answer below
The sqlite-jdbc dependency in pom.xml was set to <scope>test</scope>.
This means that the dependency is only available during the test phase and is not included in the packaged jar. As a result, when the tests are run, they can access the database driver, but when the application is packaged and run, it cannot find the driver and fails to connect to the database.

When running DatabaseSchemaTest, Maven places test-scoped dependencies on the test classpath, allowing the test suite to locate and load the SQLite JDBC driver without issues.
However, when packaging the application into a fat JAR (ticketing-service-jar-with-dependencies.jar), the assembly plugin only bundles dependencies with compile or runtime scopes, excluding any test scoped libraries. As a result, the packaged JAR lacked the SQLite driver at runtime, causing DriverManager.getConnection() to fail with SQLException: No suitable driver found.
Removing <scope>test</scope> makes the dependency available during compilation and packaging, including it inside the final JAR.

#(The constraints themselves go in DatabaseSchema.java.)
#Answer below
Primary Key is a constraint that uniquely identified each record in a database table, and it cannot contain NULL values.
A table can have only one primary key, which can consist of one or more columns (composite key).
The primary key is used to enforce entity integrity and ensure that each record in the table is unique.

UNIQUE constraint is a constraint that ensures that the values in a column or a combination of columns are unique across all records in the table.
A table can have multiple UNIQUE constraints, and they can be applied to one or more columns.
In this case, using id as the primary key is preferred over using (event_id, seat_label) because it provides a single, unique identifier for each record in the table, which simplifies queries and improves performance.
Using a composite key of (event_id, seat_label) would require additional joins and could lead to more complex queries, while using a single id column as the primary key allows for simpler queries and better performance. Additionally, using a single id column allows for easier updates and deletions of records, as the primary key value can be used to identify the record to be updated or deleted, without having to specify the event_id and seat_label values.

=== Question 7.3.1 (2 marks) ===
#Answer below
Server-side page generation is a web development approach where the server generates the HTML content of a web page and sends it to the client's browser. The work happens on the server, and the browser receives a fully rendered HTML page that can be displayed immediately.
Client-side page generation is a web development approach where the server sends a minimal HTML page to the client's browser, and the browser uses JavaScript to generate the content of the page dynamically. The work happens on the client's browser, and the browser receives a minimal HTML page along with JavaScript code that generates the content of the page.
A single page application (SPA) is a web application that loads a single HTML page and dynamically updates the content of the page as the user interacts with the application. The work happens on the client's browser, and the browser receives a single HTML page along with JavaScript code that handles the dynamic content updates. The SPA approach allows for a more seamless user experience, as the page does not need to be reloaded for each interaction, and the application can provide a more responsive and interactive experience.
